## 0. Agent 执行约束

1. 先按第 11 节目录拆模块，单文件不要堆成一个超长页面。
2. 文案、空态、按钮名、字段名按第 5、6、7 节实现，不要自行改产品范围。
3. 到店渠道必须走空态，禁止编造到店 GMV、补贴、ROI。
4. 采纳 / 忽略只记录态度，禁止做成下单、上架、发券实扣。
5. 识店本期固定命中天娱广场店，禁止接真实视觉模型。
6. 建议文案使用种子数据，禁止在没有模型服务时现场编造新建议。
7. 登录账号只有 `smartgo` / `smartgo123`。错误密码必须失败。
8. 界面禁止出现「演示」「测试」「样例」字样。
9. 地区只允许广州：天河天娱、荔湾西城都荟、海珠丽影。
10. 做完后按第 12 节逐条自测，未通过的条目写进交付说明。

## 1. 产品定义

DSR 用工号登录后，看自己片区昨日访店与销售，再拍照或从历史门店进入单店销售看板。看完看板后点「生成运营建议」，对每条建议采纳或忽略。总部监控台汇总谁去了哪家店、生成了什么、采纳了什么。导购只看已绑定门店的主推、昨日销量和当前活动。

一句话约束：**先看板，后建议；建议可表态，不伪装已执行。**

## 3. 范围

### 本期做

- 工号密码登录、退出
- 首页：到家 / 到店切换、昨日四指标、查看明细、三个角色入口
- 昨日明细：同口径四指标 + 三家访店记录，点击进看板
- DSR：拍照识店、搜索门店、历史门店
- 单店销售看板：门店信息、1KM/3KM 周边数量、高峰与品牌、活动统计、Top SKU、历史建议、生成按钮
- AI 建议：四步判断动画、采纳 / 忽略、回看
- 总部监控台：指标、漏斗、一线动态、建议回传、片区门店库
- 导购主推页
- 后端持久化：登录会话、访店记录、建议报告与采纳状态
- 种子数据与本文第 9 节一致

### 明确不做

- 对接客户门店后台的上架、订货、发券实扣
- 与客户自有门店主数据打通
- 全国经营驾驶舱、多城市报表
- 真实相机识别、真实定位反查
- 大模型在线生成建议（接口可预留，默认返回种子建议）
- 到店活动数字（三家到店能力均为否）
- 建议状态撤销（点过采纳或忽略后按钮消失）
- 微信支付、订阅消息、分享海报

## 4. 信息架构

```
登录
 └─ 首页（渠道：到家 | 到店）
     ├─ 昨日明细 → 点门店 → 销售看板

销售看板
```

| 看板 | 进入前的角色页：DSR 回 DSR 首页，总部回监控台。从昨日明细点进看板时角色记为 DSR，返回 DSR 首页 |
| 建议页 | 该店看板 |

### 5.7 销售看板

顶栏返回文案 `跑店`，标题 `销售看板`。

**门头区**

- `{零售商} · {业态} · {城市}{区县}`
- 店名、周边标签（tag）
- 地址、`nearbyDetail`
- 已覆盖平台用实心状态；未覆盖平台文案 `{平台名} 未覆盖`
- `sg_store_id {sgStoreId}`
- 抓手条：标签 `本店抓手`，标题 `opportunity.headline`，说明 `opportunity.line`

**门店标签**

副标题 `周边业态`。Tab `1KM` / `3KM`，默认 1KM。五项：社区数、医院数、学校数、商业中心数、同类商超数，取 `poiCounts` 的 `r1` 或 `r3`。下方固定说明：`业态有无来自 StoreVerse 周边标签，{半径}内数量按周边检索结果汇总。` 并展示 `nearby` 一句话。

**高峰与品牌**

- 工作日高峰：`近 90 天工作日订单最集中的时段`
- 周末高峰：`近 90 天周末订单最集中的时段`
- `近 90 天高频活动品牌：` + brands 用顿号连接

**活动统计**

副标题随时段变化：

| Tab | 副标题 | 默认 |
| --- | --- | --- |
| 昨天 | 昨日口径 · 由近 30 天推算 | |
| 近 7 天 | 近 7 天口径 · 由近 30 天推算 | |
| 近 30 天 | 近 30 天 · 标签实数 | 默认 |

每张活动卡：机制名、状态标签、`平台 · 在投天数`、活动 GMV、补贴、ROI、note。

状态映射：`good → 健康`，`broken → 断档`，`poor → ROI 偏低`。种子数据全部为 `good`，UI 仍要实现另两种样式。

**Top SKU**

副标题 `按 69 码口径`。每行：`{rank}. {name}`，`69码 {upc} · {sales}`，可选 note，右侧标签为口径（`销售额 TOP` 或 `销量 TOP`）。

**历史运营建议**

底部固定按钮 `生成运营建议`，说明 `AI 运营指导 · 结合标签、销量和机制`。

### 5.8 AI 建议

生成开始即写入报告：该店全部建议状态为 `pending`，`createdAt` 为本地 `HH:mm`。然后播放约 2.2 秒动画，四步依次点亮：

1. 检查供给：有没有货（约 0ms）
2. 检查动销：卖得好不好（约 550ms）
3. 检查机制：投得对不对（约 1100ms）
4. 检查补贴：预算够不够（约 1650ms）

标题：`按供给 → 动销 → 机制 → 补贴 逐项判断`。说明：`正在用 {店名} 的周边标签、覆盖平台销量和机制口径生成可采纳建议…`

动画结束后：

- 顶栏返回 `看板`，标题 `AI 建议`
- 提示：`无法直连门店后台做上架。请对每条建议选择采纳或忽略，采纳结果可上报总部。`
- 每条：类型标签、标题、instruction、`判断链：{chain}`、`为什么：{reason}`、`上报总部：{hqHint}`
- `pending` 时显示 `采纳`、`忽略`。点选后按钮消失，改为 `已采纳` 或 `已忽略`
- 类型标签：供给、机制、价格、季节

同一店可多次生成，每次新报告，互不影响。

**建议回传**：无报告时显示 `还没有生成记录。请先用 DSR 角色拍店并生成建议，采纳结果会出现在这里。` 有报告时每行：店名、`{时间} 生成 · 采纳 n · 忽略 n · 到家 ROI {roi}`，点击进该店看板。

**片区门店库**：三家全列，副标题 `归一门店`，行文案同搜索结果。

## 6. 业务规则

1. 渠道默认到家。首页与明细切换写同一份状态。
2. 到店只允许展示访店次数；金额与 ROI 为 `—`，并显示空态说明。
3. 未覆盖平台必须逐个显示「未覆盖」，禁止显示成一排横线。
4. 建议判断顺序固定：供给 → 动销 → 机制 → 补贴。展示用门店上已写好的 `chain`，不要在前端重算文案。
5. 采纳写入 `hqHint` 所指的计划或配券线索，只做记录。忽略不进入可配券线索。
6. 可配券线索数 = 已采纳条数，不是报告数。
7. 打开门店（拍照、搜索、历史、明细、总部列表）都把该店插入历史列表头部。
8. 商品名缺失时显示 `商品名未回传`，并保留 note，禁止补一个假名称。
9. 界面禁止露出内部字段名：`a11_peak_weekday`、`POI=`、`到家能力=`、`覆盖平台列表=`。
10. 时间文案使用：`下午 14:00-17:59`、`晚间 18:00-22:59`、`近 30 天`、`近 7 天`、`近 90 天`。

## 7. 数据模型

主键用字符串。金额、ROI、天数字段在接口里保持展示字符串，与原型一致，避免 Agent 再格式化出不一致的小数。

### Account

`id, name, loginId, passwordHash, roleLabel, region, dataDate`

### Store

与 `src/types.ts` 的 `Store` 一致，至少包含：

`id, sgStoreId, name, retailer, businessType, province, city, district, address, tags[], platformsCovered[], platformsUncovered[], peakWeekday, peakWeekend, dataDate, brands[], roiHome, aovHome, skuSupply, bestMechHome, nearby, nearbyDetail, poiCounts[], slices, advices[], yesterdaySales, yesterdayDelta, weekTrend[], hotSkus[], campaign, opportunity, guidePushes[]`

`poiCounts[]`：`key, label, r1, r3`

`slices`：`d1 | d7 | d30`，每段 `topSkus[]` + `campaigns[]`

`campaigns[]`：`id, name, platform, gmv, subsidy, roi, days, status, note`，`status` 枚举 `good | broken | poor`

`topSkus[]`：`rank, name, sku, upc, sales, note?`。这里的 `sku` 是口径标签，不是 69 码；69 码在 `upc`。

`advices[]`：`id, kind, title, chain, reason, instruction, hqHint`，`kind` 枚举 `supply | mechanism | price | season`

### AdviceReport

`id, storeId, accountId, createdAt, statuses: { [adviceId]: pending|adopted|ignored }`

### Visit

`id, accountId, dsrName, storeId, province, city, time, action, channel, gmv, subsidy, roi`

总部「一线动态」读 Visit，不从报告反推。

## 8. API

基础路径 `/api`。除登录外都带 `Authorization: Bearer <token>`。错误体：`{ "message": "..." }`。

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| POST | `/api/auth/login` | body `{ loginId, password }`。成功 `{ token, account }`，失败 401 |
| POST | `/api/auth/logout` | 作废 token |
| GET | `/api/me/summary?channel=home\|instore` | 返回四指标；到店带 `emptyNote` |
| GET | `/api/me/visits?channel=` | 昨日明细列表，含门店摘要 |
| GET | `/api/stores?q=` | 片区门店搜索，空 q 返回全部 |
| GET | `/api/stores/:id` | 门店全量，含 slices 与 advices |
| POST | `/api/stores/:id/open` | 写入历史门店（头部去重），body 可带 `{ source: "camera"\|"search"\|"history"\|"stats"\|"hq" }` |
| GET | `/api/me/history` | 历史门店 ID 顺序 |
| POST | `/api/stores/:id/reports` | 创建报告，状态全 pending，返回报告。服务端建议内容来自门店种子，不调用模型 |
| GET | `/api/stores/:id/reports` | 该店报告，新的在前 |
| GET | `/api/reports/:id` | 单份报告 + 建议正文 |
| POST | `/api/reports/:id/items/:adviceId` | body `{ status: "adopted"\|"ignored" }`。仅 `pending` 可改，否则 409 |
| GET | `/api/hq/overview` | 活跃 DSR、覆盖区县、报告数、pending 数、采纳、忽略、历史门店数、可配券线索、片区文案 |
| GET | `/api/hq/feed` | 一线动态 |
| GET | `/api/hq/reports` | 建议回传 |

登录 token 有效期 7 天即可。本期单账号，总部接口不另做权限系统，登录用户都能进三个入口（与原型一致）。

## 10. 技术方案

| 层 | 选择 | 原因 |
| --- | --- | --- |
| 小程序 | 微信原生小程序 | 页面少，避免再包一层跨端框架 |
| 接口 | Node.js + Express（或同等） | 与原型同语言生态，方便照搬种子 |
| 存储 | SQLite | 单文件可运行，满足报告持久化 |
| 鉴权 | Bearer token | 对应工号登录 |
| 样式 | 独立 wxss，按页面拆 | 对齐现有手机信息密度，深色科技风可简化为浅底清晰卡片，但信息架构不能减 |

本地同时起 API（建议 `8787`）与微信开发者工具。小程序 `baseUrl` 用配置项，禁止写死只在某台电脑可用的内网逻辑。

请求失败时页面给出 `message`，禁止静默空白。列表空态使用第 5 节原句。

## 12. 验收清单

Agent 交付前逐条勾选。

1. 空工号或空密码无法登录；`smartgo` / `wrong` 提示不正确；正确密码进入首页。
2. 首页默认到家，四指标为 3 / ¥20,220 / ¥2,391 / 8.46。
3. 切到到店后金额与 ROI 为 `—`，且出现到店空态原句；再回首页渠道仍是到店。
4. 明细三家店可进看板；天娱看板 `sg_store_id` 为 117209，抓手为 `下午档满减深挖`。
5. 看板默认近 30 天、1KM。天娱 1KM 社区数为 5，3KM 为 19。
6. 天娱未覆盖展示京东秒送、美团闪购，不出现微信支付、京东到家。
7. 搜索 `73600` 只出西城都荟；搜索 `不存在` 走空态原句。
8. 相机快门后约 2 秒进入天娱，且历史门店第一位变为天娱。
9. 生成建议时四步依次出现，然后看到天娱 4 条；采纳 1 条、忽略 1 条后按钮消失。
10. 再次进入该历史报告不重播动画，状态仍在。
11. 总部生成报告数、待处理、已采纳、已忽略、可配券线索与第 10 步一致；无操作时建议回传为空态原句。
12. 导购只显示天娱主推「康师傅 PREMIUM 优选鲜虾鱼板面杯」，无生成按钮。
13. 杀掉小程序再进，报告与采纳仍在。
14. 三家店地址、ROI、建议标题与 `src/data/stores.ts` 一致。
15. 界面无「演示 / 测试 / 样例」，无跨城门店。
