## 1. 一句话定义

DSR 拍照识别门店后，先看该店销售看板（周边标签、各平台订单、Top 商品、机制效果），再一键生成 AI 运营建议；对每条建议选择采纳或忽略。总部后台只监控 DSR 用了什么、采纳了什么，不替代经营驾驶舱。

---

## 2. 相对 v0.1 的关键调整

上一版把「一拍出答案」和导购主推做成了主路径。需求方与原项目负责人当面确认后，主路径改为：

| 原理解 | 现结论 |
| --- | --- |
| 拍照后直接给做工指令 | 拍照后先进入**销售看板**，建议由按钮 **生成运营建议 / AI 运营指导** 触发 |
| 待办勾选 = 我去上架/补货 | 无法直连客户门店后台，改成 **采纳 / 忽略** |
| 明确不做总部后台 | 做轻量 **DSR 使用监控后台**（谁去了哪家店、生成了哪些建议、采纳了哪些） |
| 导购与 DSR 并列 | DSR 为一线主路径；导购保留为后续场景 |
| 到店/到家两块销量 | 按平台拆开：微信支付、京东到家、美团闪购，并带订单、销售额、补贴 |
| 建议拍脑袋罗列 | 判断链固定为：**供给 → 动销 → 机制对不对 → 补贴够不够** |
| 门店与客户系统拉通 | **暂不拉通**。门店是 StoreVerse 里的门店 |

---

## 3. 背景与问题

一线管的门可能是新接管或以前没管过的店。总部有店级订单、补贴和机制数据，但 DSR 到店后看不到结构化看板，也无法把「这店该补货 / 该加预算 / 该停机制」沉淀成可被总部汇总的反馈。

不能把动作做成「一键上架到客户后台」：平台后台关联不上，一线只能表态采纳或忽略。

## 6. 一线主路径

```
拍照（新门/未管过）或点历史门店
        ↓
进入该店销售看板
  ① 门店信息 + 周边 1–3km 标签（社区/医院/学校等）
  ② 昨天 / 近7天 / 近30天：微信支付、京东到家、美团闪购的订单、销售额、补贴
  ③ Top 商品：单价、销售、补贴
  ④ 机制：占销售额、占补贴、是否断档、OI 好坏
        ↓
点击「生成运营建议」
        ↓
AI 按 供给 → 动销 → 机制 → 补贴 生成建议
        ↓
DSR 对每条：采纳 / 忽略
        ↓
历史生成记录可回看；采纳结果进入总部监控
```

### 6.1 销售看板字段

**周边画像**：1km 或 3km 内社区、医院、学校等，作为标签展示，并参与建议（例如社区店暑假应加补货和活动；学校旁饮料店暑假应减量）。

**平台订单**：只要该店在某平台做了活动，就把该平台销售和补贴拎出来。时间切换：昨天、近 7 天、近 30 天。

**Top 商品**：按销售排序，展示单价、销售额、补贴金额；缺货、价格异常用标记说明。

**机制**：哪些机制用得最好、占销售额多少、占补贴多少；30 天档期只投了 10 天就断 → 核销正常则判断预算不足，应追加并追核销；OI 差则建议本店停投。

### 6.2 AI 建议类型（演示必须覆盖）

| 类型 | 示例 | 判断链 |
| --- | --- | --- |
| 供给 | 缺货 SKU 补货、下补货单 | 先看有没有供给 |
| 机制-加预算 | 满减只投 10 天断档，核销正常 → 追加费用 | 机制对，补贴不够 |
| 机制-停投 | OI 差的机制不要在该店继续投 | 机制不对 |
| 价格 | SKU 售价明显高于同商圈 | 动销弱时先看价格 |
| 季节+标签 | 社区×开学/暑假加补货加活动；饮料×学校暑假减量 | 标签 × 日历 |

建议生成后允许销售「采」：觉得好或不好。**采纳**可进入下一步：汇总给总部，形成城市/渠道/门店计划；部分建议可走配券（类似支付宝申请一张新机制券）。**忽略**即不采纳。不要做成「我去上架」——关联不到客户后台。

每条建议必须写清判断链和原因。

### 6.3 历史建议

同一门店可多次生成。看板底部列出历史记录，可打开回看当时的建议及采纳状态。

---

## 7. 总部后台

后台不是经营分析驾驶舱，而是 **DSR 前端操作记录**：

- 今天哪些省、多少 DSR、去了哪些店、销售概况
- 生成了哪些运营建议报告
- 采纳了哪些、忽略了哪些

用于总部判断一线觉得哪些建议有用，再决定预算和门店动作。门店主体是 StoreVerse 数据，拉通客户门店不在本期（即便做，也在后台做）。

## 9. 交互原则

1. **先看板，后建议**：没有点击生成前，不把建议当成第一屏。
2. **建议可表态、不伪装已执行**：采纳/忽略，不假装已经上架到对方系统。
3. **单店上下文**：看板和建议都只讲这一家店。
4. **原因可见**：每条建议能回答判断链上的哪一步出了问题。
5. **总部看行为，不看大盘**：后台回答「一线用了没有、采没采」，不回答全国 GMV。

## 11. 演示脚本

**脚本 A（主讲）：DSR 拍翡翠湾店**

1. 选择 DSR，拍一拍永辉门头。
2. 进入销售看板：社区/学校标签，微信支付/京东到家/美团闪购，切换近 30 天。
3. 看到开学季满减只投 10 天断档、台灯价格异常、文具缺货。
4. 点「生成运营建议」，展示供给→动销→机制→补贴。
5. 对补货、追加预算、停投差机制等分别采纳或忽略。
6. 切到总部后台，看到本会话生成报告与采纳数。

**脚本 B：历史门店**

从历史门店进望京店，看板以到家晚高峰为主，建议先补供给再谈补贴。

**脚本 C（可选）：导购**

仍可进入我的门店看主推，不作为本轮讲解重点。

## 14. 附录：面聊结论

1. 进店先看销售看板：标签、各平台订单与补贴、Top 商品、机制。
2. 建议是生成出来的，不是看板默认展开的待办。
3. 判断顺序：有没有供给，动销好不好，机制对不对，补贴够不够。
4. 一线动作是采纳或忽略；上架/订货做不到客户后台。
5. 总部后台统计 DSR 使用与采纳，便于做计划和配券。
6. 门店用 StoreVerse 的，本期不跟客户门店拉通。
